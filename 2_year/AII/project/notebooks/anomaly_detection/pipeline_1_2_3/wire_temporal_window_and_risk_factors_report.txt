=== PART A: temporal_window/1_fixed_policy.ipynb, wired to the deployed scores ===
Fixed policy: every patient gets the same 6-month interval, no
patient information used at all -- the zero-information floor DIDI is 0 by
construction; cost/catch are what a completely undifferentiated policy costs.

  Snapshot adaptive (2_snapshot_adaptive) cost=   5123.4  DIDI=1.281  catch= 65.8%
  Trajectory adaptive (3_trajectory_adaptive) cost=   5307.6  DIDI=4.273  catch= 74.0%

All three of temporal_window's patient-information policies are now wired to
the actual deployed pipeline (forecast_adaptive excluded -- needs multi-horizon
forecast columns this pipeline doesn't produce). Read the progression fixed ->
snapshot -> trajectory as the real, cumulative value of each successive piece of
patient information: none, current risk level, current risk level plus direction.

=== PART B: risk_factors/1_global.ipynb's method, wired to the deployed scores ===
Lasso (signed, linear) and Random Forest (feature_importances_) regressed
against RISK_SCORE, plus SHAP on the forest -- three vantage points on 'what
drives this score, at the population level', applied to BOTH the plain and the
fair calibrated score, to see whether the fairness mechanism leans on a
genuinely different set of biomarkers, not just a shifted output.

n=1420 rows with the full extended+anomaly feature set available.

Largest shift in what drives the score: NOMINAL_MONTH (+0.3404).
If PTAU/TAU/AMYGDALA_NORM-style biomarkers stay dominant for both and the
shifts are small, that confirms explainability_fairness.py's earlier finding
(with the OLD constant-shift fix) still holds for the ACTUAL deployed
ExponentiatedGradient mechanism too: fairness correction changes the OUTPUT
distribution, not which biomarkers the score is actually built from. A large
shift would be a genuinely new finding worth flagging -- it would mean the fair
model isn't just a recalibrated version of the plain one, it reasons differently.
